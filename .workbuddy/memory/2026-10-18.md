# 2026-10-18 · 硅基记忆体 MVP 从 0 到可运行

## 做了什么

在空目录 `~/WorkBuddy/硅基记忆体/` 从零搭起「以人为单位的 Agent 容器」MVP，交付四件套（架构 / 交互 / 小程序 demo / 费用），并跑通两条流程。

## 核心设计（后续改动要守住）

- **四概念**：碳基档案（facts/episodes/traits）→ 硅基体（人格包）→ 生活服务 Agent（声明 needs/provides）→ 核对回路。
- **声明式依赖是架构支点**：agent 之间不互相调用，`needs: ['context.fortune']` 由编排器自动补齐 provider。新增服务只加一个文件，编排核心不改。
- **LLM 是增强层**：`LLM_PROVIDER=none` 时规则引擎跑全流程。任何 LLM 失败返回 null 降级，绝不阻断。
- **不做向量检索**：标签倒排 + 时间衰减，因为可解释（能说清"因为你在 10/16 记过胃不舒服"）。
- **置信度 90 天半衰期**；事实冲突不自动覆盖，进 conflict 队列让人裁决。
- **gather 场景必须组装成「一个局」**（本+场地+茶歇+时间线+待办+人均），不能平铺三组推荐 —— 这是多 agent 协同的价值点。

## 验证结果

- `node server/scripts/smoke.js`：33 项全通过（含错误路径 400/404）。
- 吃什么：「今天中午吃什么，一个人，别太辣，预算30」→ 蒿子面 0.86，理由含"胃不舒服时最稳妥 / 18 元份量刚好 / 不辣"，溯源到"2 天前夜宵吃辣"。
- 组局：「周六 6 人，预算150，没玩过的多」→ 《雾隐山庄》+ 家里客厅 + 轻食拼盘，人均 110，时间线 19:00→23:10，4 项待办。

## 踩过的坑（下次直接避开）

- **curl 走代理连不上 127.0.0.1**：必须加 `--noproxy '*'`，否则报 `upstream connect failed`。
- **Bash 后台进程会被回收**：服务必须用 `run_in_background: true` 启动，`(node ... &)` 在下一个工具调用前就没了。
- **WXML 模板不支持 indexOf**：选中态必须预计算 `cls`，否则静默失效。已写 `miniprogram/scripts/check-wxml.js` 拦三类问题。
- 三道菜理由一开始完全一样 → 改为 category 去重 + 与第一名对比（省多少钱/快几分钟）。
