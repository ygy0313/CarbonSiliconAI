# 隐私与授权：脱敏存储、票据提取、标准导出

> 一句话原则：**记录在写入之前就已经不是隐私了。** 之后的每一步取用，都要票据。

## 一、数据的三种形态

```
用户输入一句话
   │
   ├─① 原文（含手机号/身份证/地址……）
   │     └─ AES-256-GCM 加密 → episodes[].rawCipher      只进保险箱
   │
   ├─② 脱敏文本（<手机号1><证件号1><地址1>……）
   │     └─ episodes[].text                              进主库，供推荐与展示
   │
   └─③ 结构化事实（diet.spicy=微辣 …）
         └─ facts[]                                      进主库，本来就是标签
```

- 主库里**永远查不到原文**。想还原，要两把钥匙：授权票据（证明用户同意）+ 保险箱口令（证明是本人）。
- 保险箱密钥由口令 scrypt 派生（N=2^15），密钥只在进程内存，不落盘、不进日志、不进导出文件。
- 演示数据（seed）走同一条脱敏流水线 —— 不存在「这条是 demo 所以留明文」的例外口子。

## 二、脱敏规则（`src/security/redact.js`）

| 类型 | 示例 | 处理 |
|---|---|---|
| 身份证 | 640102199001011234 | → `<证件号1>` |
| 手机号 | 13800001234 | → `<手机号1>` |
| 银行卡 | 6222 0202 … | → `<银行卡1>` |
| 邮箱 | a@b.com | → `<邮箱1>` |
| 社交账号 | 微信：laowang_888 | → `微信：<账号1>`（保留「微信」二字，句子可读） |
| 详细地址 | …市…区…路3号楼2单元501 | → `<地址1>` |
| 精确坐标 | 38.48719,106.2309 | → `<坐标1>` |
| 姓名 | 我叫杨光宇 | → `我叫<称呼1>`（只在明确句式里，避免误伤地名） |

占位符 ↔ 原值的映射表整体加密存 `episodes[].piiCipher`。同一类型的多个值按出现顺序编号，还原时不串位。

正则不是万能的（识别不了「我表姐在XX局」这种间接泄露），它是**成本为零、可回归测试**的基线；
上了多人之后该接 NER / 内容安全接口，接的位置就在 `redact.js`，别的代码不用动。

## 三、授权票据（`src/security/grant.js`）

四种 scope，各自独立签发：

| scope | 能做什么 |
|---|---|
| `prompt` | 读取由档案编译出的人格 prompt |
| `export` | 生成标准导出文件 |
| `raw` | 导出文件里附带加密原文（仍需口令才能解） |
| `pii` | 还原身份信息字段 |

票据规则：

1. **明文只出现一次** —— 签发接口返回一次，库里只存 sha256 指纹（`tokenHash`），列表页永远看不到它
2. **有期限**（默认 15 分钟，上限 24 小时）、**有次数**（默认 1 次，上限 50）、**有用途**（必填）
3. **scope 隔离** —— 拿导出票读不了 prompt（403），拿 prompt 票导出不了文件
4. **全程审计** —— `grant.issue / grant.use / grant.deny / grant.revoke / export.create` 全落 `audits` 集合，用户随时回看「谁在什么时候要过什么」
5. **票据只走请求头** `X-Grant-Token`，绝不进 URL（query 会进访问日志）

小程序端的票据只存内存（`app.globalData.tokens`），退出小程序即失效 —— 宁可重签一次，不让票据在手机上过夜。

## 四、标准导出（`qijuzhu/v1`）

```jsonc
{
  "format": "qijuzhu/v1",
  "version": "0.2.0",
  "exportedAt": "2026-10-18T…",
  "depth": "safe | prompt | sealed",     // 导出深度，由票据 scope 决定
  "checksum": "sha256(canonical(payload))",
  "signature": "hmac(保险箱密钥, checksum)",  // 保险箱未解锁时为 null
  "payload": {
    "person":   { "id": "…", "name": "（起居注用户）" },  // 默认不带真名
    "facts":    [ … 完整度、置信度、来源 ],
    "episodes": [ … 脱敏文本 + redaction 审计 ],
    "prompt":   "…（需 scope=prompt）",
    "sealed":   { "items": [密文原文] … }                // 需 scope=raw
  }
}
```

- **checksum** 用键排序的稳定序列化计算，任何一处被改动校验即失败（回归里专门测了篡改场景）
- **signature** 用保险箱密钥做 HMAC —— 只有同一口令的持有者能验证「这份文件确实出自我的档案」
- **导入恢复**：`POST /api/import` 校验格式与 checksum 后，事实与记忆写入一个**新**档案，
  置信度降为 `restored` 来源，evidence 链保留 —— 恢复出来的档案不会冒充原始记录
- 导出文件本身**可分享**：`safe` 深度不含任何身份信息，可以直接喂给另一个 agent 当画像

## 五、prompt 提取（用户问的「提取个人 agent 中的 prompt」）

`GET /api/persons/:id/prompt`，需 `scope=prompt`。返回的 prompt 只包含脱敏后的内容，
因为原料本身就只有脱敏文本 —— **不存在「prompt 里漏出明文」的可能性**。

prompt 结构：硬性约束 → 已确认档案 → 待核实的旧判断 → 最近发生的事 → 说话风格 → 行为统计。
其中「硬性约束」写死了四条，包括「没有记录的偏好不许编」「运势只谈节奏不作吉凶断言」。
