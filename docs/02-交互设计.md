# 起居注 · 交互与设计逻辑

> 版本 v2.0 ｜ 2026-10-26 ｜ 对应 `miniprogram/` 五个 tab + 五个功能页
>
> v1 那份描述的是「深色底、三个 tab、首页推推荐」的早期形态，已作废。
> 这份是当前线上形态：纸白底、五个 tab、首页六个模块、档案与我的合并成一页。

## 一、产品是什么

一句话：**起居注是一个「先记住你、再替你算」的私人生活助理。**

- 产品名 **起居注**（皇帝的日常记录），助手名 **执笔**（记录的人）。
- 它比通用助手多做的一件事是「记」：每句话落成记忆，记忆归纳成经验，经验反过来影响下一次推荐。
- 它比通用助手少做的一件事是「编」：不报价、不解梦、不谈吉凶、不装懂。宁可说「还没接通」，不说「我猜」。

三个角色的关系：

```
你 ──说一句──▶ 执笔（编排） ──调能力──▶ 六个生活服务
                    │                      │
                    ◀──── 结果 + 理由 ─────┘
                    │
                记住这件事（记忆 → 事实 → 经验）
```

## 二、六条设计原则

1. **结果先行，不做天窗。** 首页每一格都直接给出算好的结果，不是一排「点我开始」的按钮。空的是数据，不是布局。
2. **每条推荐都能被追问。** 卡片永远带「为什么」；能引到具体记忆的要引（`evidence`）。说不清理由的建议不该出现。
3. **修正比输入省力。** 不要求用户「完善档案」，只要求他看到不对时点一下 —— 12 个维度点开即改，冲突只在他自己看到时问一次。
4. **推荐是算的，日程是定的。** 吃、动、喝是执笔算给你看的，随时可换；日程是你自己认下的承诺，只有你点头才落地。
5. **界线写进界面，不只写在法务文档。** 不报价（只给价位带）、不解梦（只拆意象）、不谈吉凶（只谈节奏），这些话直接印在卡片上。
6. **数据归用户，看得见摸得着。** Prompt 可看、档案可导出、授权有记录、动账有账本 —— 这是产品的一部分，不是设置里的小角落。

## 三、信息架构

```
┌ 执笔（首页）
│  问候 → 身份条 → 今日五行 → 今天吃什么 → 动一动 → 日程 → 喝点什么 → 记个梦
│                                              └→ 说一句（chat）→ 方案详情（plan）→ 写进日程
├ 记录（tab）
│  写字 / 拍照 / 说话 → 存 → 它理解成了什么 → 改了哪些事实 → 有冲突去核对
├ 日程（tab）
│  加一件事（今天/明天/后天/择日 + 可选时刻）→ 按天分组 → 勾完 → 删
├ 经验（tab）
│  经验资产（可用/待确认/休眠）→ 有效性 → 双环：改标准要你确认
└ 我的（tab）
   三段：档案（我是谁）｜身体（我现在怎么样）｜数据（它怎么看我 + 数据归谁）
```

设计取舍：

- **为什么首页六个模块**：这六件事覆盖了「一天里真正会想的事」——今天什么日子、吃什么、动不动、要做什么、喝什么、梦见了什么。再多的入口都不该放首页，放「服务市场」。
- **为什么日程单独成 tab**：日程要有落点才能被信任。首页只摊今天三件，全部在 tab 里增删，组局方案采纳后自动写一条进去。
- **为什么档案并进我的**：两个页面各讲一半（档案讲事实，我的讲数据与授权），用户要来回跳才能拼出「你到底知道我什么」。现在一页三段，跳的是段，不是页。

图标语言：**单个汉字的印章块**（历 / 食 / 动 / 程 / 饮 / 梦），深绿底白字，与头像、「三件事」的序号圆点是同一套印章语言。不用 emoji —— 彩色表情在纸白 + 深绿的版面上会散掉焦点。

新人（完整度 < 30%）在身份条下多一块「先做三件事」：同意三件事 → 入局问答 → 记第一笔。这块随 `homeMode` 可手动切回老用户视角。

### 2. 说一句（chat）

- 空态给三句示例，示例即教程。
- 提交后先播编排轨迹（识别意图 → 载入档案 → 召回服务 → 依赖解析 → 执行），逐条浮现，再出结果。这一秒半不是加载动画，是让「结论不是凭空蹦出来的」变得可见。
- 结果卡：主推 + 备选 + 「依据」引用具体记忆；按钮只有两个 —— 采纳 / 不要。

### 3. 方案详情（plan）

组局类结果落到这一页：这么排的原因 → 当天时间线 → 由谁提供 → 要办的事（可勾）→ 就这么定。

**「就这么定」不是一句 toast**：采纳后写一条日程（标题 = 方案名，日期 = 方案落定的那天，时刻 = 时间线第一节点），首页与日程 tab 立刻能看到。这是「推荐 → 承诺」的唯一通道。

### 4. 记录（record）

写一句话（可拍照识食、可按住说话转写），存完立刻回三件事：它把这句话理解成什么、改动了哪些事实、有几处跟原来的说法对不上（对不上给「去核对」，跳到「我的 · 档案」裁决）。

### 5. 日程（agenda）

```
日程
这里只放你自己认下的事。执笔的推荐要你点头才落地。

┌ 要做什么，一句话就够                    ┐
│ [今天] [明天] [后天] [其他日子]         │
│ [定个时刻]                              │
│ [记下这件事]                            │
└─────────────────────────────────────────┘

今天            10 月 26 日
┌ ○ 牙医                                  删 ┐
│   09:00                                     │
│ ● 周六 6 人局   19:30 · 6 人                │
└─────────────────────────────────────────────┘
明天            10 月 27 日
…
```

日期边界一律按北京时间算（服务端 `agenda.service` 统一换算），分组的「今天/明天/后天/周X」由服务端给，前端不重复计算。勾完是先就地翻状态再发请求，失败回滚 —— 勾选是高频动作，不该等一个来回。

### 6. 我的（三段一页）

```
(起) 给自己起个昵称           8 / 12 项
     档案完整度 71% · 点名字可改昵称

[ 档案 ]  [ 身体 ]  [ 数据 ]
```

| 段 | 内容 | 为什么放这 |
|---|---|---|
| 档案 | 完整度条 → 冲突裁决（琥珀）→ 饮食/社交/生活/自我四组共 12 维（点即改，带置信度条）→ 个人八字（出生信息 → 四柱 + 五行分布） | 都是「我是谁」 |
| 身体 | 微信运动（今日步数 + 近 7 天柱状 + 落档案）→ 手动记一笔（用药/睡眠/体重/其他） | 都是「我现在怎么样」 |
| 数据 | 它现在这样理解你 → 最近的记忆 → 我的 Prompt（自动签 15 分钟 3 次授权）→ 授权记录（可撤销）→ 数据账本（只追加）→ 法律文本 → 开发设置 | 都是「它怎么看我、数据归谁」 |

**置信度条是这一页的灵魂**：它诚实标出「这条信息有多可靠」（0.5 以下转琥珀），而不是假装什么都确定。

## 五、两条核心流程

### A. 今天吃什么

```
首页/说一句 ──▶ 编排器 ──▶ 节律(fortune) ──▶ 天气 ──▶ 膳食(meal)
                   │                                      │
                   │◀── 3 道菜 + 每条理由 + 溯源记忆 ──────┘
                   ▼
            卡片：菜名 / 热量 / 人均 / 时长 / 两条理由
                   │
                   ├─ 换一道 → 本地轮换候选（不重新算）
                   ├─ 去大众点评搜 → 复制「菜名 + 城市」
                   └─ 采纳 → 记一笔（评分反馈进经验）
```

### B. 组局 → 日程

```
「周六想和朋友组个局，6 个人」
        │
        ▼
日程核对（读真实日程，不是猜）──▶ 这天有没有别的事
        │
        ▼
选本 + 场地 + 茶歇 并行 ──▶ 仲裁成一个「局」
        │
        ▼
方案详情：时间线 / 待办 / 人均
        │
        └─ 就这么定 ──▶ 反馈落库 + 写一条日程 ──▶ 首页「日程」与 tab 立刻可见
```

## 六、状态与边界

| 场景 | 处理 |
|---|---|
| 后端连不上 | 降级到内置演示数据，顶部一行「离线演示 · 后端未连接」；写操作明确提示不会保存 |
| 单个能力失败 | 只影响它那一格（该模块显示「拿不到…」），其余照常出结果 |
| 定位被拒 | 模块照常给结果，改按档案城市；卡片上给「允许定位」直跳系统设置 |
| LLM 未配置 | 返回 `null` 走规则降级，文案说「还没接通」，不说「没认出来」 |
| 推荐为空 | 说清原因（「就这一条合适，不用换」/「拿不到运动建议」），不白屏 |
| 档案冲突 | 只在「两个值都可信且不一致」时出现，琥珀色，用户自己裁决 |
| 未同意隐私政策 | 只看不写：同意层挡住写操作，顶部留一条「还没同意」的提醒条 |
| 识图 / 录音 | 只在内存过一遍就丢，不落盘、不进档案；界面明说「没有保存」 |

## 七、视觉规范

| 项 | 值 | 用途 |
|---|---|---|
| 纸白底 | `#FBFAF8` | 页面底色 |
| 白卡 | `#FFFFFF` + 极轻阴影 | 内容承载 |
| 星巴克绿 | `#00704A` | 主色：确认、进度、主动作 |
| 深绿 | `#1E3932` | 印章块、Prompt 代码块 |
| 文字 | `#1F2320` / `#5B655F` / `#7A847E` | 主 / 次 / 弱 |
| 分隔线 | `#E7E2D9` | 行分隔，不用边框堆层次 |
| 琥珀 | `#96690F` | 冲突、方案、需要你定的事 |

- 字阶：52 / 44 / 36 / 32 / 30 / 28 / 26 / 24 / 22 rpx。
- 圆角：卡片 24rpx，按钮 46rpx（胶囊），chip 999rpx，印章块 10rpx。
- 设计令牌只在 `miniprogram/app.wxss` 与 `web/style.css` 的 `:root` 里改，页面不许写死颜色。
- 分区的固定写法：`.section`（左绿竖条标题 + 右侧「全部 ›」）+ `.card`（内容）。**`.section` 不承载内容** —— 早期把它当容器用，导致横向挤压。

## 八、界面与红线的对应

| 红线 | 落在哪个界面 |
|---|---|
| 原文不落主库 | 记录页「先抹掉再存」的说明；我的页 Prompt/导出必须签授权 |
| 读原文要票据 | 我的页「查看我的 Prompt」自动签 15 分钟 3 次，用完进授权记录 |
| 每条推荐有 why | 所有卡片带「· 理由」，能溯源的带「依据」 |
| 经验必须影响结果 | 经验页展示应用次数与奏效率；编排时经验参与仲裁 |
| 改标准要双环 | 经验页改阈值必须 `confirm:true`，并写进审计 |
| 选酒不报价 | 喝点什么卡片只给价位带 + 「价格以店铺为准」 |
| 记梦不解梦 | 记个梦只出意象、情绪、频率，明确写「不解释含义」 |
| 五行不谈吉凶 | 今日五行卡片底部固定免责句 |
| 识图录音不留存 | 记录页拍照/录音后的提示语「没有保存」 |
